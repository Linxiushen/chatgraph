# ChatGraph 工程验收与产品边界

日期：2026-09-21；修复版本：0.4.2-beta.1；审查基线：`38460fdf7d684693adb1774ae8846405dd2c20a5`。

当前可交付的是**单拥有者、单服务进程的个人知识工作区测试版，以及 Android 测试 App / 待签名 iOS App**。下面区分已经运行验证的能力、明确的平台限制和商业上线所需外部条件。编译成功、模拟浏览器成功、真机成功、正式上架是不同的验收结论。没有“所有 bug 已消失”的承诺，新增缺陷必须进入可复现回归。

## 1. 本轮实际修复与故障验收

| 工程面 | 本轮处理 | 自动化证据 |
| --- | --- | --- |
| 付费任务身份 | UUID 绑定规范请求摘要，更换原文/参数返回 409；摘要不含 Key | `test/jobs.test.mjs`：重启、重复提交、输入变更 |
| 取消与网络不确定 | 取消落盘竞态不进入模型；取消请求失败保留 UUID，继续查询原任务 | jobs / editor 浏览器故障注入；一次模型调用 |
| 桌面关页后找回 | 明确入口列出其他窗口的整理，用户手动接管后查原 UUID；保存成功才清旧收据 | 真实关闭标签页、新 owner、仅一次任务和模型调用 |
| 原文和图谱持久化 | 文件先 fsync 再原子替换；POSIX 同步父目录；失败保留原件 | `test/storage-reliability.test.mjs`：写入失败、原件字节一致 |

| 登录过期 | 同页重新登录，保留当前输入，不跳走丢失编辑 | editor 浏览器；桌面截图人工复核 |

## 2. 默认验收命令

```sh
node --test chatgraph/test/*.test.mjs
node --test chatgraph/extension/test/*.test.mjs
npm run test:browser --prefix chatgraph
node chatgraph/integrations/browser-check.mjs
node chatgraph/mobile/browser-check.mjs
node chatgraph/scripts/deploy-check.mjs
bash chatgraph/mobile/ios/scripts/check-source.sh
```

浏览器需要 Playwright；Docker 演练需要 Docker；iOS 源码检查需要 macOS Swift。Android 执行 `:app:assembleDebug :app:lintDebug :app:testDebugUnitTest`。完整 iphoneos 编译在 macOS CI 执行。CI 另外运行 Node 20 兼容性、Node 24 主回归、MCP/OAuth、依赖审计、提取包启动与原生构建；固定 Playwright 版本。CI 失败不得发布，旧通过记录不能替代改变后的路径。

自动测试使用临时数据和虚构模型响应；真实模型评估用显式 `test:live` 命令，结果与耗费另记。最新执行结果见 [VALIDATION.md](../VALIDATION.md)。

## 3. 正式上线前的外部验收

| 外部条件 | 需要完成的动作 | 完成标准 |
| --- | --- | --- |
| 公网运行环境 | 配置服务器、域名、TLS、私密模型配置与持久卷 | 手机蜂窝网络可登录、导入、生成、重启恢复；公网 TLS 验证成功 |
| Android 正式身份 | 确定包名，生成并安全备份长期发行密钥，用同一密钥签后续版本 | 正式签名 APK 安装和覆盖升级；进程死亡、本地数据迁移通过 |
| iOS 正式身份 | Apple 团队、Bundle ID、App Group、主 App/扩展 profiles、签名与分发 | 真 iPhone 安装，系统分享和 App Group 实际跨进程读写通过；TestFlight/审核结果单列 |
| 真机与系统矩阵 | Android 8/主流新版本、iOS 16/主流新版本、低内存、横竖屏、第三方文件提供器 | 分享文本/URL/UTF-8文件、拒绝非法文件、杀进程、断网重连、空间不足、升级均无原文丢失 |
| 浏览器与辅助技术 | Safari、Chrome/Edge 实际版本、PWA安装、VoiceOver/TalkBack、键盘和200%字号 | 可完整完成选择范围、编辑、纠错、导出；按钮可达、无关键遮挡 |
| 平台接入 | 在真实 ChatGPT/DeepSeek 网页测页面采集；ChatGPT MCP配 OAuth/真实账号 | 页面改版仍能识别角色/范围；权限拒绝有恢复入口；官方连接/审核实际通过 |
| 运维责任 | 定时备份、异机副本、容量和可用性监控、故障通知接收人 | 恢复演练记录、备份新鲜度目标、故障处置人、密钥轮换演练 |

这些条件不能由一个 ZIP 代替。仓库没有持有用户的发行私钥、Apple 账号、公共域名和目标真机；未伪造上述验收。Android 当前 debug 签名可能随构建环境变化，升级不能保证覆盖安装；卸载前必须先转存收件。iOS 当前 IPA 未签名，普通 iPhone 不能直接安装。

## 4. 产品功能已经考虑到的范围

| 用户目标 | 当前处理 | 后续扩展前必须解决的条件 |
| --- | --- | --- |
| 从 AI App 保存思考 | 主动系统分享、粘贴、文件、浏览器扩展、Safari快捷指令 | 不能后台读取其他原生 App 的私有聊天；系统权限也不允许任意读取 |
| 保存完整上下文 | 来源、角色、范围预览，明确遗漏/部分内容 | 仅分享 URL 没有原文时需补正文；自动抓取须单独适配平台，不绕过登录 |
| 整理事实与个人判断 | 区分用户/AI/共同/未知、确认/否定/修正、真实引用 | 结构有效不等于事实准确；模型质量需要真实语料、人审标注与回归基准 |
| 后续积累与再利用 | 追加、全文检索、AI关联建议、可编辑导出 | 跨库去重/向量检索应先定义规模目标和依据，避免误合并相反观点 |
| 多设备使用 | 同一 HTTPS 服务登录、服务器保存、revision冲突保护 | 没有自动合并两个设备的并行修改，也没有自动同步设备临时收件箱 |
| 离线使用 | 可暂存手机收件、保留浏览器草稿 | AI生成和服务器知识库需要联网；离线完整编辑/同步需冲突与本地加密方案 |
| 可迁移和可删除 | 图谱JSON/全库备份、历史恢复、分享撤回、原生收件清空 | 图谱删除是可恢复删除，历史/任务可能仍含原文；“永久删除所有副本”须另做明确确认、保留策略及备份删除机制 |
| 多格式交付 | Markdown、JSON、SVG、HTML、可编辑PPTX | 图片/语音/PDF/OCR附件理解、自动长文创作不是当前已完成能力 |
| 协作与收费 | 当前单拥有者私有工作区、只读访客分享 | 多租户需逐资源授权、账户恢复、隔离存储/任务、计费/配额、防滥用及审计，不能直接给多人共用一个密码 |

这些扩展是明确的下一阶段产品能力，不以添加空按钮、伪造权限或返回假数据标记“完成”。是否加入当前版应由真实使用频率和错误成本决定。

## 5. 运维与兼容性约束

- 同一数据目录只允许一个服务进程；没有跨进程数据库锁，不支持集群或多个副本共写。多个浏览器/手机可访问同一个服务。
- 历史图谱如果超过新 8 MiB 总量边界，会显示需要恢复，原文件保留。升级前全量备份；超大知识库通过停机快照迁移。
- 删除 API 新增必需 expectedRevision；老页面须刷新，否则收到 428 且不删除。模型任务旧回执没有摘要，继续恢复旧结果，不自动重新执行。
- 收件箱是最多 5 份/50 MB/24 小时的临时存储，不是永久知识库；系统清理应用数据/卸载/清除浏览器会删除本地内容。
- 历史与任务回执不自动清理。无人值守部署需要数据卷监控和人工决定保留策略；不能为省空间擅自删除付费结果或历史。
- 本地数据文件不是端到端加密。HTTPS保护传输；服务主机管理员可以读其数据，AI模式会向配置的模型服务发送所选内容。
- 健康端点只证明 HTTP 活着；没有声称具备集中式 metrics、全天值守、生产 SLA 或大规模压力认证。上线后应针对预计图谱数/并发数建立 p95 延迟、内存、错误率、恢复时间和备份新鲜度目标。
- 快照需要停机一致性；备份本身含私人对话，应安全保存。恢复到新目录、验证后切换、保留旧数据，是可回滚路径。详细命令见 [部署手册](../deploy/README.md)。

## 6. 持续维护规则

每个真实缺陷应留下：触发输入、受影响版本、期望行为、修复和可重跑回归。模型质量缺陷保留去标识样本与期望的归属/引用，不把生产私人聊天上传 CI。每次发布检查 core/browser/native/container gates、许可证、版本一致性、SHA-256、升级和回滚说明；已发布版本不覆盖。依赖高危告警必须处置或给出明确适用性证据。

正式上线的优先顺序是：已有数据和付费任务可靠 → 真机安装/分享/升级 → 可达部署与备份监控 → 真实用户复用与模型质量 → 根据证据增加团队和商业能力。
